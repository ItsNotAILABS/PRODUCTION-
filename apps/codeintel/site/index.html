The loop

Three calls. The order matters, which is why they're numbered.

01

Index once

Submit files. They're parsed to symbols and line spans, then the text is discarded — only the derived index persists. Re-submitting unchanged content is a no-op.

# POST /v1/repos/{repo}/files
{"files":[{"path":"pricing.py","content":"..."}]}
→ 21 symbols · card is 8% of the file
02

Find it

Ask in plain words. BM25 over symbol names, signatures and docstrings, weighted so a name beats a docstring beats a filename. No embeddings, no model call.

# GET /v1/repos/{repo}/search?q=optimal price from elasticity
→ optimal_price · pricing.py:L84–99
03

Read only that

Get the span back with line numbers, so an edit writes back against the coordinates it read from. Two symbols share a name? You get a 409 with both candidates, never a silent guess at the wrong file.

# POST /v1/repos/{repo}/read_symbol
{"name":"optimal_price","path":"pricing.py"}
→ 894 B served · 7,832 B if read whole

Your source

The reason enterprises can actually deploy this.

discardedFile text sent to /files is parsed and thrown away. What persists is symbol names, line spans, docstring first lines, and a content hash. Nothing reconstructs the file.
never stored/read takes the content to slice in the request. The service never becomes a second copy of your repository.
isolatedEvery index and query is scoped to the calling account. Two customers using the same repo name see nothing of each other — there's a test asserting it, not a promise.
hashedAPI keys are stored as salted SHA-256. The plaintext is shown once at creation and is unrecoverable. The stored prefix cannot authenticate.
on-premCan't send source over the wire at all? The identical application runs inside your perimeter. That's the enterprise tier — self-hosting is the product, not a downgrade.

What it doesn't do

Worth knowing before you buy, not after.

python onlyLine spans are exact for Python via a real AST parse. JavaScript and TypeScript come from a regex scan and are flagged exact: false — fine to navigate with, not to edit against blindly. Other languages get metadata only.
lexicalSearch matches wording, not meaning. It finds optimal_price from “optimal price from elasticity” because those words are present. A symbol whose purpose is only inferable will be missed.
coarseRate limiting is a fixed per-minute window, so it's approximate at boundaries. Adequate for abuse control; not a fairness guarantee.
single nodeSQLite backs the index. Comfortable to low millions of symbols on one box; a multi-node deployment wants Postgres.
