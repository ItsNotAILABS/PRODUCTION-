Get a key

Two doors, and the second one needs nothing from us.

# 1 · hosted — self-serve, free tier, key returned once
curl -X POST https://your-instance/v1/signup \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@company.com"}'
→ {"api_key":"lc_…","plan":{"slug":"free","max_indexed_lines":25000}}

# 2 · self-host — the identical application, inside your perimeter
export LOOM_KEY_SALT=$(openssl rand -hex 32)
export LOOM_SIGNUP=1                      # open self-serve on your instance
docker compose up -d
docker compose exec loomcode python admin.py account create you@co.com --plan team
open http://localhost:8080/docs           # generated OpenAPI, always current
shown onceThere is no password and no session, so the signup response is the only time the key exists in readable form. It is stored as a salted SHA-256 hash and cannot be recovered — only replaced.
closed by defaultSelf-serve is off unless an operator sets LOOM_SIGNUP=1. When on, it provisions the free plan only, one account per address, with an hourly ceiling per source — a public endpoint that mints credentials should not also be a key vending machine.

API

Every endpoint. Bearer token, JSON in, JSON out.

endpointwhat it does
POST/v1/signupFree account + first key. Public, off by default.
POST/v1/repos/{repo}/filesIndex files. Text is parsed and discarded; unchanged content is a no-op.
GET/v1/repos/{repo}/searchRank symbols by a natural-language query. Returns the signals behind each placement.
POST/v1/repos/{repo}/context_packThe one most agents want. Budgeted pack: span, callees, callers, siblings, file cards — all cited.
GET/v1/repos/{repo}/graphEdge counts by confidence tier.
GET/v1/repos/{repo}/relationsCallers, callees and external calls for one symbol.
GET/v1/repos/{repo}/importantThe repo map — PageRank over the call graph.
GET/v1/repos/{repo}/cardThe shape of one file, at ~8% of its bytes.
POST/v1/repos/{repo}/read_symbolA symbol's exact span. 409 with candidates if the name is ambiguous.
POST/v1/repos/{repo}/readA line range, clamped and flagged if out of bounds.
GET/v1/repos/{repo}/locateEvery symbol with an exact name.
GET/v1/usage · /v1/accountBilling basis, value delivered, remaining headroom.

Every call edge says how much was known.

tiermeaninghow it can be wrong
exactOne definition of that name in the same file.It can't — local scope resolves it.
likelyOne definition in the whole repo.An import of a same-named third-party symbol.
ambiguousSeveral share the name — all recorded.It doesn't guess; you get every candidate.
externalNot indexed — a dependency or builtin.Kept, not dropped: a leaf calling an SDK isn't self-contained.

whyCharging per request would punish you for the tool working — the entire value is fewer, smaller calls. So the meter is the size of the estate under management. /v1/usage reports context saved separately and says plainly that it is the value delivered, not the thing being charged for.

What it doesn't do

Worth knowing before you build on it.

no embeddingsSearch is lexical plus structural. There is a DenseProvider slot and nothing ships in it — the moment an embedding model is in the request path, the claim that a request costs CPU and nothing else is gone. An earlier build tried a dependency-free hashing pseudo-embedding; across 7,641 symbols the collisions ranked an unrelated activation function above the pricing model being searched for. Bring your own and it fuses as a fourth ranker.
no stemmingWords match as written. Searching reorder widgets will not match a symbol named widget_reorder_threshold on the word widgets — only its docstring matches, and a shorter-named neighbour like reorder_point can outrank it on BM25 length normalisation. Try it in the playground above; it is rank two, not rank one. Query with the words the code uses.
name-basedResolution matches the trailing name, so a.b.parse(x) resolves as parse. Receiver types aren't inferred — which is exactly why the confidence tier is on every edge instead of hidden.
coarseRate limiting is a fixed per-minute window, so it's approximate at boundaries. Adequate for abuse control; not a fairness guarantee.
single nodeSQLite backs the index. Comfortable to low millions of symbols on one box; a multi-node deployment wants Postgres.
