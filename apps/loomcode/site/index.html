loomcode selective retrieval for coding agents

Stop paying to read files you don't need.

To change six lines, your agent loads whole files — and you're billed for every token of it. Loom Code parses the repo once, resolves its call graph, then returns a budgeted pack: the span that matters, what it calls, what calls it, and citations for all of it. The pipeline

Four stages. The order matters, which is why they're numbered.

01

Parse

Real ASTs, not regex. Python via the stdlib; everything else via tree-sitter, so end lines are true and you can edit against them. Text is parsed and discarded — only the derived index persists.

# POST /v1/repos/{repo}/files
{"files":[{"path":"pricing.py","content":"..."}]}
→ 30 symbols · card is 8% of the source
02

Resolve

Call sites become edges, each tagged with how much was actually known. A graph that hides its guesses is worse than none — an agent follows the wrong edge into the wrong file and never learns the edge was a guess.

# GET /v1/repos/{repo}/graph
→ 26 edges · 5 exact · 6 likely · 15 external
03

Rank

Lexical BM25, direct name match, and PageRank centrality each produce their own ordering; Reciprocal Rank Fusion combines the positions. Fusing positions, not scores, is what makes it safe — BM25 and PageRank have no defensible exchange rate.

# GET /v1/repos/{repo}/search?q=optimal price from elasticity
→ optimal_price · signals {lexical:1, name:1, central:3}
04

Pack

Fill a token budget in priority order: matched span, callees, callers, the file's other symbols by name, then cards for other files. Every tier is capped so one hot function with sixty callers can't eat the budget. Whatever doesn't fit is reported, not dropped.

# POST /v1/repos/{repo}/context_pack
{"query":"optimal price from elasticity","budget_tokens":1200}
→ 791 used · 409 headroom · 0 omitted · every element cited

Confidence

Every edge says how much was actually known.

tierwhat it meanshow it can be wrong
exact One definition of that name in the same file. It can't. Local scope resolves it.
likely One definition in the whole repo. An import of a same-named third-party symbol would fool it.
ambiguous Several definitions share the name. All are recorded. It doesn't guess — it hands you every candidate.
external No definition indexed — a dependency or a builtin. Kept, not dropped: a leaf that calls into an SDK isn't self-contained.
weightedConfidence feeds PageRank: a guessed edge moves less rank than a resolved one, and an ambiguous call fanning out to four candidates contributes a quarter as much. Otherwise a hub forms purely because the name get is popular.

Languages

Exact line spans, from a real parse.

Python stdlib ast Go TypeScript JavaScript PHP Pascal / Delphi Java Rust Ruby Kotlin
not a guessThe previous release scanned everything but Python with a regex and marked the spans approximate. That was honest but useless: you cannot edit against a boundary found by looking for the next declaration. These are real parses.
per grammarEach language needed its own correction. Go files a method's receiver first, so a naive read indexes Total as c. Delphi declares a routine twice — interface and implementation — and writes procedure TCatalog.Total, where the leading name is the owner, not the member. There are tests for both.

Your source

The reason enterprises can actually deploy this.

discardedFile text sent to /files is parsed and thrown away. What persists is symbol names, line spans, docstring first lines, call sites, and a content hash. Nothing reconstructs the file.
never stored/read and /context_pack take the content to slice in the request. The service never becomes a second copy of your repository.
isolatedEvery index, edge and centrality score is scoped to the calling account. Two customers using the same repo name see nothing of each other — there's a test asserting it for the derived graph too, not just the index.
hashedAPI keys are stored as salted SHA-256. The plaintext is shown once at creation and is unrecoverable. The stored prefix cannot authenticate.
on-premCan't send source over the wire at all? The identical application runs inside your perimeter. That's the enterprise tier — self-hosting is the product, not a downgrade.

Run it

Self-hosting is the product, so that is the quickstart.

# the whole thing, on your own machine
export LOOM_KEY_SALT=$(openssl rand -hex 32)   # required; rotating invalidates keys
docker compose up -d

# accounts and keys are created via shell, never over HTTP
docker compose exec loomcode python admin.py account create you@co.com --plan team
docker compose exec loomcode python admin.py key issue acct_xxx --label ci

# interactive API docs are generated from the app itself
open http://localhost:8080/docs
no signupThere is no hosted tier to sign up for yet, so this page does not pretend otherwise. Everything on it — the numbers, the video, the call graph — came from an instance running exactly these commands.
no keys neededNothing phones home. No model API key, no telemetry endpoint, no license check. docker compose up is the entire dependency list.

What it doesn't do

Worth knowing before you buy, not after.

no embeddingsSearch is lexical plus structural. There is a DenseProvider slot and nothing ships in it — the moment an embedding model is in the request path, the claim that a request costs CPU and nothing else is gone. An earlier build tried a dependency-free hashing pseudo-embedding; across 7,641 symbols the collisions ranked an unrelated activation function above the pricing model being searched for. Bring your own provider and it fuses as a fourth ranker.
name-basedResolution matches on the trailing name, so a.b.parse(x) resolves as parse. Receiver types aren't inferred — which is exactly why the confidence tier is on every edge instead of hidden.
coarseRate limiting is a fixed per-minute window, so it's approximate at boundaries. Adequate for abuse control; not a fairness guarantee.
single nodeSQLite backs the index. Comfortable to low millions of symbols on one box; a multi-node deployment wants Postgres.
