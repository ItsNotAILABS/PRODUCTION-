loomcode how it works

Four stages. No embeddings, no GPU.

Every request costs CPU and nothing else. That is what makes it sellable per-seat instead of per-token — and self-hostable inside your own perimeter.

01

Parse

Real ASTs for ten languages. Exact end lines, so you can edit against them — not a regex guessing where the next declaration starts.

02

Resolve

Call sites become edges, each tagged with how much was actually known. It never silently guesses which validate you meant.

03

Rank

BM25, name match and PageRank centrality fused by RRF — positions, not scores. BM25 7.4 and PageRank 0.003 have no exchange rate.

04

Pack

Fill a token budget by priority, every tier capped. Anything cut is reported with a reason, never dropped in silence.

loomcode the part nobody else ships

Every edge says how much was actually known.

A call graph that hides its guesses is worse than no graph: your agent follows a wrong edge into the wrong file and never learns the edge was a guess.

exact One definition of that name in the same file. It cannot be wrong — local scope resolves it.
likely One definition in the whole repo. An import of a same-named third-party symbol would fool it.
ambiguous Several share the name — every candidate is recorded. You get all of them. It does not pick one and hope.
external Not indexed — a dependency or a builtin. Kept, not dropped: a leaf calling into an SDK is not self-contained.
Confidence feeds PageRank — a guessed edge moves less rank than a resolved one.
