## PART IV — EDGE MESH PROTOCOLS

### 4.1 — Heartbeat Synchronization
All Edge AIs synchronize to the central 873ms heartbeat within ±50ms tolerance.

### 4.2 — Phi-Weighted Routing
Request routing uses phi-weighted latency scoring:
```javascript
score = (1/latency) * (health/100) * PHI
bestEdge = edges.reduce((a,b) => score(a) > score(b) ? a : b)
```

### 4.3 — Automatic Failover
Edge failures trigger automatic failover within 2 heartbeats:
1. Detect failure (heartbeat missed)
2. Calculate nearest healthy edge
3. Reroute traffic
4. Notify monitoring

### 4.4 — Federated Learning
Edge AIs participate in federated learning:
- Local model updates from edge traffic
- Aggregated centrally every 1000 heartbeats
- Privacy preserved via differential privacy

## PART V — EDGE AI GOVERNANCE

### 5.1 — Authority Limits
Edge AIs may:
- ✅ Process requests locally
- ✅ Cache responses
- ✅ Spawn local microbots
- ✅ Report metrics

Edge AIs may NOT:
- ❌ Modify core protocols
- ❌ Access other edges' data
- ❌ Override central governance
- ❌ Persist user data without consent

### 5.2 — Health Reporting
Every 10 heartbeats (8.73 seconds), each Edge AI reports:
- Request count
- Error rate
- Average latency
- P99 latency
- Cache hit rate
- Health score

### 5.3 — Defensive Mode
On critical threat detection, Edge AIs enter defensive mode:
- Rate limiting activated
- Suspicious IPs blocked
- Traffic rerouted to healthy edges
- Alert escalated to SENTINEL
